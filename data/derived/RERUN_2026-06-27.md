## P1 (blocker) — FIXED. But the brief's stated root cause was WRONG; the real one is worse-diagnosed below.

- The 1.0000 tag-jump cutoff did **not** come from "the positive control's own cell being included."
  The code already excluded the PC cells. In this run the **16 PC (mackerel) wells are essentially
  empty** — 14 have 0 reads, `PC_plate3`=10,739 (which is *Gasterosteus*/stickleback, not mackerel),
  `PC_plate4`=1 — and **none of the 26 Scomber-assigned ASVs has any read in any PC well.** The spike
  never sequenced, so there was no bleed signal to calibrate against.
- Actual mechanism: `calib = max(within-ASV fraction)` over all 26 Scomber ASVs, **21 of which are
  singletons** (one library each → fraction = 1.0 by construction). The max was driven by ASV0308
  (1,116 reads, all in field lib E01_R3_T15) → calib = 1.0. It measured "most concentrated rare ASV",
  not mackerel bleed.
- **Fix:** restrict the spike estimate to Scomber ASVs actually present in PC wells; since none are,
  fall back to the **pre-registered default per-ASV index-hop floor 0.001 (0.1%)** — retains **77.54%**
  of detections (matches your sweep). A hard count-integrity gate now refuses to write a degenerate table.
